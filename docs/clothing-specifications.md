# 服装推薦仕様の設計メモ

- Issue: https://github.com/shu-saginoya/otenki-code/issues/49
- 作成日: 2026-06-18

## 目的

このアプリのコア機能である「気温に応じた服装の推薦」についてデータ構造・仕様を検討する。
「簡単にカスタマイズできる」と「詳細にカスタマイズできる」を両立させる。
データ構造としてはなるべくセマンティックに直感的にわかりやすくつくる。

- 服装データのあり方
- 服装と気温をどのように関連付けるか
- それらはデフォルト値をもつ
- それらはカスタマイズできるようにもする

### 非対象（いったん除外）

- 天気（雨/風/湿度）を考慮した推薦
- 時間帯（朝晩）による推薦切り替え
- 機械学習による自動最適化

なお、トップス・ボトムスは最高気温で算出され、アウターは通勤時間帯の気温で算出される。
しかし、これらは服装と気温の関連付けには関与しない。
服装と気温の関連付けはあくまで気温に対してのみ設定し、それが最高気温なのか通勤時間帯の気温なのかは責務外とする

## 設計方針

### 関心の分離

`ClothingItem` は「服そのもの」の情報だけを持つ。  
気温との対応は別モデル（ルール）で表現する。

## データ構造

データベースで扱いやすい構造にする。

### 服装

- ID
- 名前
- カテゴリー（トップス・ボトムス・アウター）
- アイコン
- デフォルト値か
- ユーザーID（カスタム値の場合）

### 服装と気温の関連付け

- カテゴリー
- 気温と服装を関連付けたオブジェクト（例：`{ minTemp, clothingItemId }[]`）

#### 服装と気温の関連付けについてルール

- カテゴリーごとにデータを管理する
- それぞれは、気温の最低ラインと対応する服装のIDを記憶する
- 推薦は気温`temp`に対して`minTemp <= temp`を満たす要素のうち**最大の `minTemp`**の服装を採用する
- 最低気温未満で未定義にならないよう、各カテゴリは`minTemp = -Infinity`相当の先頭要素を必ず持つ
- 同じ気温には1つの服装しか登録できないようにする（重複禁止）
- 保存は境界値となる気温だが、編集（UI）は区間（0～4℃など）で扱ってよい
- 昇順で保存
